# Project Discovery and Baseline

## Intake

Собери и зафиксируй до разработки:

| Поле | Что определить |
| --- | --- |
| Цель | Какое действие, понимание или впечатление должен создать сайт |
| Аудитория | Роль, контекст визита, уровень знания продукта, язык |
| Story | Последовательность сообщений и доказательств по экранам |
| Арт-дирекция | Утверждённые master-кадры, референсы, палитра, типографика, запреты |
| Сцены | Назначение, медиа, ожидаемая динамика и scroll-механика |
| Интеграции | Форма, аналитика, CRM, consent, домен и окружения |
| Технологии | Framework, styling, animation, тесты, deployment/runtime |
| Приёмка | Брейкпоинты, браузеры, performance и критерий утверждения видео |

Отделяй утверждённые факты от предположений. Помечай вопрос, если ответ меняет визуальный язык, семантику сцены, стоимость генерации или выпуск в production.

## Инвентаризация существующего сайта

Создай baseline-таблицу до изменения:

| Область | Проверить | Зафиксировать |
| --- | --- | --- |
| Страницы | Роуты, якоря, 404, начальная загрузка | URL и владельца компонента |
| Сцены | DOM, фон, sticky/scroll logic, fallback | Назначение, триггер, риск |
| Медиа | Master, poster, public output, размеры, кодек | Путь, aspect ratio, размер, источник |
| Форма | Required-поля, валидация, endpoint, ошибки | Ожидаемый путь лида и UX |
| Навигация | Desktop/mobile, фокус, URL, active-state | Брейкпоинт и поведение |
| Motion | GSAP/observers/listeners, cleanup, reduced motion | Точки запуска и обратимость |
| Tooling | Scripts, test runner, build, deploy docs | Команды и фактический результат |

Используй браузерную проверку, а не только чтение исходников. Снимай скриншоты критических состояний: начало, середина и конец длинной сцены; мобильный header/menu; форма; reduced motion.

## Архитектурные принципы

- Рендери ключевой копирайт и CTA в HTML, пригодном для SEO, выделения и screen reader.
- Предусматривай poster и статичное состояние до загрузки и при ошибке видео.
- Учитывай `object-fit`, focal point, aspect ratio и возможную обрезку до подключения видео.
- Разделяй исходники (`masters`, reference, candidates) и веб-оптимизированные файлы (`public/media`).
- Не помещай API-ключи в клиентский код, исходники, документацию или console output.
- Считай текущее состояние документом, а не памятью сессии: указывай выбранные версии asset и временные отключения.

## Шаблон baseline-отчёта

```md
## Baseline — YYYY-MM-DD

### Работает
- …

### Риски и баги
- [P0/P1/P2] область — наблюдаемое поведение, способ воспроизведения, вероятная причина.

### Сцены
| ID | Состояние | Контракт | Media | Fallback | Проверка |
| --- | --- | --- | --- | --- | --- |

### Решения, требующие подтверждения
- …
```

Не меняй исходный материал, если diagnosis можно провести через чтение, локальный build или отдельный тестовый output.
