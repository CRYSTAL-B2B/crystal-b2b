### P1 — блокеры релиза

#### CR-P1-01 — «System → Processes» не реализует обязательный narrative transition

- **Файлы:** `src/components/scenes/SystemProcesses.tsx:5-58`; требования: `docs/scenes/02_SYSTEM_PROCESSES.md`.
- **Доказательство:** компонент серверный и рендерит только sticky `Image` (`:17-25`) и `ol` из восьми строк (`:33-53`). В нём нет client-state, observer, GSAP, timeline, SVG/DOM-слоёв, меняющихся классов или взаимодействия. Текущий visual QA подтверждает статичный левый кадр и обычную прокрутку списка.
- **Почему это P1:** сцена 02 — один из пяти основных актов и должна доказывать, что система связана, а не является набором инструментов. В текущем виде она именно превращается в перечень инструментов.
- **Исправление:** реализовать не менее трёх явно различимых состояний: целостная система → выделение/сборка восьми процессов → видимые связи/поток между ними. Не использовать accordion как замену сцене. Оставить полный HTML-текст в DOM и reduced-motion summary.
- **Сложность / риск:** L; основной риск — перегрузить мобильный интерфейс. Сначала зафиксировать storyboard и acceptance screenshots.
- **Проверка после исправления:** Playwright фиксирует состояние до/после scroll; E2E проверяет отсутствие accordion-паттерна, наличие состояния/связей; manual QA 360, 768, 1440 px и reduced motion.

#### CR-P1-02 — Control the Flow и Lighthouse заявляют трансформации, но в runtime показывают готовые статичные кадры

- **Файлы:** `src/components/scenes/ControlFlow.tsx:13-73`, `src/components/scenes/Lighthouse.tsx:15-69`; требования: `docs/scenes/03_CONTROL_THE_FLOW.md`, `docs/scenes/05_LIGHTHOUSE.md`.
- **Доказательство:** обе сцены создают GSAP timeline, однако визуальная часть — единый `<Image>`; timeline меняет лишь opacity/position copy и scale/translation кадра. В JSX нет сущностей потока, потерь, feedback, сигнала, маршрута или стадий их изменения.
- **Почему это P1:** пользователю обещается не декоративный фильм, а наглядное доказательство управляемого потока и маршрута из турбулентности. Текст сообщает это, но визуальная сцена не подтверждает.
- **Исправление:** для Flow показать исходный поток, точки утечки/потерь, управляющие воздействия и замкнутый feedback-loop; для Lighthouse — последовательность «шум/турбулентность → появление сигнала → маршрут». Использовать отдельные DOM/SVG-слои и короткие дискретные состояния; кадровая иллюстрация может остаться художественной основой, но не единственным носителем смысла.
- **Сложность / риск:** L; риск ухудшения LCP и снижения читабельности. Бюджеты и fallback из раздела Performance обязательны.
- **Проверка после исправления:** визуальные эталоны старт/середина/конец, обратный scroll без дрейфа, keyboard/reduced motion, ручная проверка ясности без чтения текста.

#### CR-P1-03 — интерактивные trace controls в Connected System не выполняют обещанную функцию

- **Файлы:** `src/components/scenes/ConnectedSystem.tsx:9-13, 74-107`; `src/app/globals.css:1402`.
- **Доказательство:** событие hover/focus/click меняет `activeTrace`, а значит только `data-trace` на контейнере (`:74`). Внутри — один готовый `Image` (`:76-85`). В CSS для trace найдено только изменение `filter`; DOM-слоёв связей, animation path или выделяемых маршрутов нет. Кнопки выглядят как работающий контрол, однако пользователь не получает путь «content», «response» или «data».
- **Почему это P1:** это явная интерактивная функция центральной сцены; ложная affordance подрывает доверие сильнее, чем отсутствие кнопки.
- **Исправление:** отрисовать доступные overlay-маршруты/узлы в DOM или SVG поверх художественного кадра, изменять именно выбранный путь и добавить текстовое состояние для screen reader. Если интерактивность не будет создана, убрать кнопки и представить связи статично, не имитируя управление.
- **Сложность / риск:** M; риск — низкий контраст линий на растровом кадре. Нужны тестируемые `data-*` состояния и различимый визуальный output.
- **Проверка после исправления:** screenshot по каждому trace, `aria-pressed`, keyboard Tab/Enter/Space, axe и проверка contrast.

#### CR-P1-04 — основная lead-форма недоступна для реальной конверсии в проверенной production-конфигурации

- **Файлы:** `src/app/api/lead/route.ts:63-69`; `.env.production.local`; `deploy/crystal-b2b.service`.
- **Доказательство:** endpoint честно возвращает 503, если `LEAD_WEBHOOK_URL` не задан. В доступном локальном production env этот параметр отсутствует; сервисная конфигурация не задаёт альтернативный канал. Нынешний UI не выдаёт ложный успех — это правильно, но CTA «Обсудить задачу» не приводит к доставленной заявке.
- **Почему это P1:** это ключевая conversion-точка сайта. Проверка формы на 503 полезна как fallback, но не является готовностью продакшена.
- **Исправление:** до выпуска подключить подтверждённый HTTPS endpoint/CRM/mail relay, хранить secret только в runtime environment, ввести idempotency/request ID и провести реальный end-to-end smoke test с получением заявки. Не записывать webhook в репозиторий или отчёт.
- **Сложность / риск:** S/M; зависит от владельца канала доставки. Риск данных снижается только после подтверждённой доставки.
- **Проверка после исправления:** отправка тестовой заявки на production, подтверждение приёма у получателя, повторная отправка/ошибка upstream и запись результата в release checklist.

### P2 — исправить в ближайшей итерации

#### CR-P2-01 — production загружает GSAP для трёх далёких сцен сразу после hydration

- **Файлы:** `src/components/scenes/ControlFlow.tsx:13-73`, `ConnectedSystem.tsx:20-63`, `Lighthouse.tsx:15-69`, `src/lib/gsap.ts`.
- **Доказательство:** все три client-компонента присутствуют в первоначально отрендеренной странице, и каждый запускает `getGsap()` в `useLayoutEffect`, не ожидая близости viewport. Dynamic import уменьшает стартовый HTML bundle, но фактически запрашивается сразу после hydration. Из собранного HTML: **183,1 КБ gzip JS**; CSS — **14,98 КБ gzip**. Внутри установленного бюджета JS, но стратегия «загружать motion near need» не соблюдена.
- **Исправление:** запускать import/ScrollTrigger после `IntersectionObserver` с разумным `rootMargin` (например 800–1200px), единым loader и защитой от повторной инициализации. Не создавать ScrollTrigger для offscreen сцены.
- **Сложность / риск:** M; протестировать быстрый scroll и возврат назад.

#### CR-P2-02 — временный TypographySwitcher попал в production UI и перекрывает контент на mobile

- **Файлы:** `src/app/page.tsx:29`, `src/components/ui/TypographySwitcher.tsx:23-70`, `src/app/globals.css:3858-3912`.
- **Доказательство:** контрол всегда монтируется, fixed поверх контента. README и PLANS называют его временным инструментом review. В mobile visual QA он накладывается на proof/визуальные зоны и добавляет пользователю не относящийся к задаче выбор A/B/C.
- **Исправление:** убрать из production render либо скрыть за явным review-only feature flag, не доступным публичному пользователю. Если выбор остаётся продуктовой функцией — дать ему отдельную настройку без перекрытия и обосновать ценность.
- **Сложность / риск:** S; обновить E2E, которые сейчас проверяют переключатель.

#### CR-P2-03 — клиентская отправка формы может зависнуть в состоянии «Отправляем…» без лимита времени

- **Файлы:** `src/components/sections/ContactForm.tsx:48-68`.
- **Доказательство:** server-to-webhook запрос ограничен 8 секундами, но browser `fetch('/api/lead')` не имеет `AbortController`/timeout. При проблеме соединения до ответа Next.js кнопка остаётся disabled неограниченно долго.
- **Исправление:** добавить клиентский abort timeout, понятную retry-подсказку, отмену в cleanup и сохранение заполненных полей. Удержать server timeout как независимый защитный слой.
- **Сложность / риск:** S.

#### CR-P2-04 — rate limit формы можно обходить подменой X-Forwarded-For; он не масштабируется между процессами

- **Файлы:** `src/app/api/lead/route.ts:6-25`; `deploy/nginx/crystal-b2b.conf`.
- **Доказательство:** ключ берётся из первого значения клиентского `x-forwarded-for` (`route.ts:10-13`), а nginx использует `$proxy_add_x_forwarded_for`. Клиент может прислать собственный XFF и менять первый IP. Хранилище — in-memory `Map`, поэтому сбрасывается при restart и не разделяется между replicas.
- **Исправление:** доверять только корректно нормализованному адресу от известного proxy (или `X-Real-IP` после явной очистки входящих заголовков); перенести лимит в nginx/Redis/провайдера. Добавить лимит тела на proxy/stream уровне, а не только `Content-Length`.
- **Сложность / риск:** M; необходимо согласовать реальную сетевую топологию и не заблокировать пользователей за NAT.

#### CR-P2-05 — mobile menu не удерживает keyboard focus внутри полноэкранного overlay

- **Файлы:** `src/components/layout/Header.tsx:13-26, 44-72`.
- **Доказательство:** при открытии фокус переводится на первую ссылку и Escape обрабатывается, но Tab/Shift+Tab не циклируют фокус, background не получает `inert`, роль dialog отсутствует. После последней ссылки фокус может перейти под закрывающий экраном overlay.
- **Исправление:** либо сделать меню настоящим `dialog` с focus trap и возвратом focus, либо оставить обычной навигационной панелью, не перекрывающей документ. Выбрать один семантический паттерн и покрыть Tab/Shift+Tab тестом.
- **Сложность / риск:** S/M.

#### CR-P2-06 — в production CSS остались крупные неиспользуемые procedural-правила и obsolete scroll-настройки

- **Файлы:** `src/app/globals.css:372-630, 765-1005, 1059-1223, 1406-1597, 2214-2364`; актуальная разметка `src/components/**/*.tsx`.
- **Доказательство:** после visual reboot JSX больше не содержит `hero-visual`, `process-stage`, `process-origin`, `architecture-layer`, `storm-field`, однако связанные стили остаются. Итоговый CSS небольшой (69,7 КБ raw / 15,0 КБ gzip), поэтому это прежде всего риск поддерживаемости, ложных regressions и дорогого следующего редизайна, а не текущий P1 performance fault.
- **Исправление:** удалить мёртвые блоки и связанные media/reduced-motion варианты отдельным чистым PR; до удаления сопоставить selector → компонент и выполнить visual diff.
- **Сложность / риск:** M; каскад CSS может содержать неочевидные общие токены.

#### CR-P2-07 — `qa-artifacts/` отражает старую реализацию и больше не является достоверным evidence

- **Файлы:** `qa-artifacts/`, текущие `src/components/scenes/*`.
- **Доказательство:** сохранённые изображения показывают предыдущую procedural-версию Processes, тогда как текущий компонент — static sticky/list. Это создаёт риск ложного sign-off и затрудняет расследование регрессий.
- **Исправление:** после P1 переснять именованные desktop/mobile/reduced-motion baseline для актуального commit; хранить manifest с URL, viewport, browser, commit SHA и датой. Старые файлы перенести в явно помеченный архив или удалить из QA source-of-truth.
- **Сложность / риск:** S.

## Ответы на обязательные вопросы

### 1. Что сломается первым при росте трафика?

Lead endpoint: in-memory rate limit не разделяется между instances, сбрасывается при restart и допускает обход через XFF. Затем проявится ранняя инициализация GSAP на каждой загрузке длинной страницы: это не авария, но лишняя работа на low-end mobile и медленной сети.

### 2. Где главным UX/доверительным риском был baseline?

Пользователь видит интерактивные пути в Connected System, но контрол не показывает выбранный путь. Второй риск — CTA предлагает обсудить задачу, однако сейчас форма честно сообщает, что канал не настроен. Оба случая создают разрыв между обещанием и реальным действием.

### 3. Что проверить вручную перед релизом?

Проверить реальную доставку заявки от формы до ответственного человека; пройти все пять сцен без чтения сопроводительного текста на 360/768/1440 px; нажать каждый trace и увидеть однозначную разницу; пройти mobile menu только клавиатурой; включить reduced motion; снять Lighthouse mobile throttled и проверить LCP/INP/CLS; проверить Nginx/IP rate-limit с реальными заголовками proxy.
