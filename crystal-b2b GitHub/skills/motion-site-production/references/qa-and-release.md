# QA and Release

## Матрица приёмки

| Область | Что подтвердить |
| --- | --- |
| Содержание | Копирайт, язык, CTA, логика сцен и ссылка на актуальные assets |
| Визуал | Master/poster/video совпадают с утверждённой арт-дирекцией, нет неожиданных границ и кропа |
| Motion | Вход, середина, конец, fast scroll, back-scroll, restart и resize устойчивы |
| Responsive | 320 px, основной mobile, tablet и desktop не дают overflow или перекрытия |
| Media | Верные URL, MIME, aspect ratio, poster, ошибка загрузки и autoplay policy |
| Accessibility | Keyboard, focus, labels, контраст, semantics, reduced motion |
| Functional | Меню, якоря, форма, валидация, успех и ошибка работают |
| Tooling | Lint, typecheck, tests и production build проходят |
| Production | Новые assets реально попали в deployed bundle и smoke-check подтверждён |

## Обязательная последовательность

1. Просмотри текущие docs, deploy-инструкцию и `git status`.
2. Запусти доступные проверки в порядке: format/lint, typecheck, unit, build, browser/E2E.
3. Выполни ручной visual QA по матрице на реальном viewport.
4. Зафиксируй результаты тестов и известные ограничения в документации.
5. Коммить только изменения, происхождение которых известно; не добавляй чужие dirty-файлы.
6. Выполняй деплой или restart только в рамках подтверждённой процедуры проекта.
7. После релиза проверь публичный URL, критические assets, меню, форму и целевые сцены.

## Защита от stale build

Для framework/runtime с generated manifest:

- не считай перезапуск процесса достаточной проверкой;
- подтверждай, что production build был создан после изменения assets и кода;
- проверяй, что долгоживущий процесс использует именно новый output;
- при ошибке отсутствующего build-артефакта сначала диагностируй mismatch между текущим процессом и build, не удаляй output вслепую;
- фиксируй последовательность build/restart/smoke в deploy runbook проекта.

## Документация на выпуск

Обновляй только уместные источники правды проекта:

- `CURRENT_STATE` или эквивалент: реальные feature flags, активные/отключённые сцены, selected media;
- `PLAN`: завершённые и оставшиеся этапы;
- video runbook: master, prompt, кандидат, утверждение и delivery path;
- README/deployment: актуальные команды и окружение;
- changelog/release note: пользовательский эффект, а не только список файлов.

Не документируй секреты, личные данные, внутренние endpoint-параметры или значения env.

## Формат финального handoff

```md
## Готово
- Краткий пользовательский результат.

### Изменено
- Файл/сцена — что стало иначе.

### Проверено
- Команда или ручной сценарий — результат.

### Открыто
- Только решение, которое действительно требует пользователя.
```

Не заявляй о production-релизе, если выполнены только локальные проверки.
