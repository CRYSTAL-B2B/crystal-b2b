# Scene Contracts

## Правило

Определи сцену как контролируемую трансформацию: пользователь должен суметь ответить, что было, что изменилось и зачем это важно. Декоративное движение не заменяет эту трансформацию.

## Карточка сцены

Заполняй карточку до реализации. Храни её в brief, plan или документации проекта.

```yaml
id: 03-control-flow
purpose: "Показать, как команда управляет потоком, а не реагирует на хаос."
message: "Контроль возникает из видимости маршрута и следующего действия."
static_copy:
  eyebrow: "SYSTEM / CONTROL"
  heading: "Control the flow"
  body: "…"
start_state: "Несвязанные сигналы/узлы без выделенного маршрута."
meaningful_change: "Появляется читаемый маршрут, точки контроля и следующее действие."
end_state: "Поток видим и управляем; CTA объясняет следующий шаг."
trigger: "scroll range 15–80% контейнера"
reverse: "Да, возвращает читаемое начальное состояние."
desktop: "sticky visual, copy advances by steps"
mobile: "тот же маршрут в видео/постере без scroll lock"
reduced_motion: "показывает end-state и все ключевые связи статично"
media:
  poster: "public/media/first-frames/03-control-flow.webp"
  video: "public/media/video/03-control-flow.webm"
  source: "assets/generated/..."
acceptance:
  - "Маршрут виден с первого просмотра end-state."
  - "На back-scroll нет обрывов и залипших классов."
  - "Копирайт не перекрывает ключевой объект."
```

## Pattern library

| Сюжет | Видимое изменение | Неудачная подмена |
| --- | --- | --- |
| Поток/процесс | Сигнал проходит этапы, статус и выход меняются | Медленно движущийся фон с надписью «Process» |
| Маршрут/trace | Активный путь связывает исходную точку, решение и результат | Кнопка, которая ничего не раскрывает |
| Контроль | Появляются границы, owner, сигнал и следующее действие | Один только zoom в абстрактную схему |
| Connected system | Отдельные узлы становятся системой с направленными связями | Декоративные линии без причинно-следственной связи |
| Lighthouse | Есть ориентир, направление, движение к/от него и ясный итог | Статичный пейзаж с ярким источником света |

## Реализация scroll-сцены

- Выделяй независимый container, trigger и lifecycle; не полагайся на глобальное состояние предыдущей сцены.
- Держи состояние idempotent: повторный enter, back-scroll и resize дают тот же результат.
- Используй `IntersectionObserver` для простых enter/exit-событий; используй timeline/ScrollTrigger только когда непрерывная прогрессия действительно нужна.
- Создавай и уничтожай animation instances в жизненном цикле компонента.
- Не перехватывай wheel/touch-события для «кинематографичности», если нет явного UX-требования и проверки accessibility.
- Не меняй позицию video-wrapper во время scroll, если арт-дирекция требует фиксированный кадр; анимируй содержимое или таймкод, а не layout.
- Ограничивай `will-change` активными элементами и отключай тяжёлые эффекты за пределами viewport.

## Responsive и accessibility

- Сохраняй смысл на 320 px, tablet и desktop; не принимай desktop как единственный source of truth.
- Используй корректные заголовки, label у каждого поля, видимый focus и логичный tab order.
- Показывай статичную финальную композицию при `prefers-reduced-motion: reduce`; не прячь критическую информацию.
- Предусматривай видео без autoplay: poster, controls только по необходимости, понятная ошибка загрузки.
- Тестируй visibility текста поверх светлого и тёмного участков video/poster.

## Проверка сцены

Для каждой изменённой сцены проверь:

1. Первый кадр, среднюю точку и финальное состояние.
2. Вход со страницы и прямой переход к её якорю.
3. Быструю прокрутку вниз и вверх, затем resize.
4. Desktop, mobile и reduced-motion fallback.
5. Отсутствие горизонтального overflow, перекрытий и «зависших» классов/таймлайнов.
