## Контекст

Аудит живого сайта (28 скриншотов desktop 1440 / mobile 390, замеры позиций блоков, разбор кода) дал оценку 68/100 с вердиктом «запускать после правок». Сайт сделан выше среднего по рынку: сильный первый экран, кейсы с цифрами по схеме «проблема → система → результат», короткая форма. Ограничивают его четыре вещи:

1. **Не сказано, что покупают.** Страница объясняет идею системности, но не называет формат услуги, состав работ, срок и цену. Цены существуют только в `src/data/faq.ts` и видны лишь на отдельной странице `/faq`.
2. **Доказательства приходят поздно.** Высота страницы 20 351 px (desktop) / 21 663 px (mobile). Первые цифры (`#results`) — на 9 583 px, кейсы (`#cases`) — на 11 466 px, форма — на 19 363 px (95% глубины). Половину пути человек читает рассуждения, не увидев ни одного доказательства.
3. **Два равнозначных действия.** «Обсудить задачу» (форма) и «Определить курс» (Google-календарь) стоят рядом в шапке, в мобильном меню и под формой. По названиям невозможно понять разницу.
4. **Нет независимых подтверждений** — ни отзывов, ни фотографии, ни логотипов; все цифры звучат только от первого лица.

Плюс подтверждённый измерением баг: на ширине 390 px подпись под кнопкой формы («Нажимая кнопку… Созвон — 30 минут, онлайн») уезжает за правый край экрана — именно в момент решения человек не видит, что произойдёт после клика.

**Ожидаемый результат:** посетитель за первую половину страницы получает доказательства, понимает формат и цену, видит одно понятное действие и подтверждения от третьих лиц.

## Особенности кодовой базы — прочитать до начала

1. **Весь CSS — один файл `src/app/globals.css`, 5862 строки, со слоистыми переопределениями.** Один и тот же класс объявляется по 2–4 раза, и побеждает последнее объявление (пример: `.cases-section` фон — простой цвет на строке 1851, перебит градиентом с фото на 4117). **Никогда не правьте первое найденное вхождение — сделайте `grep -n` по всему файлу и найдите побеждающее.**
2. **Новые правила добавлять в конец файла**, иначе их перебьют существующие поздние блоки.
3. **Скриншот вместо чтения CSS.** Дважды в истории проекта чтение CSS давало неверную картину того, что реально рендерится. Проверяйте браузером.
4. **Опорные брейкпоинты:** 960 px (шапка, сетки) и 768 px (типографика, форма, контейнер).
5. **Деплой ручной.** Auto-deploy на GitHub Pages отключён: после `git push origin main` владелец должен вручную запустить Actions → Deploy Pages. **`git commit` без `git push` = деплой уедет со старым кодом** — эта ошибка уже была.
6. Сборка статическая (`output: "export"`), `images.unoptimized: true` — `next/image` использовать можно, оптимизации не будет.
7. Скрипты: `npm run build`, `npm run lint`, `npm run typecheck`, `npm run test` (vitest), `npm run test:e2e` (playwright).

## Правка 1. Мобильная подпись под кнопкой формы (баг вёрстки)

**Приоритет: сделать первой** — самая дешёвая и полностью проверяемая.

### Причина (установлена точно)

`.form-submit-actions { flex: 1 1 100% }` — `globals.css:5123-5129`, объявлено **вне медиазапроса**, поэтому действует и на мобильном. В связке с `.form-submit { flex-wrap: wrap; gap: 1.5rem }` (`globals.css:2724-2730`) и `flex-direction: column` (`globals.css:3540-3543`, `@media ≤768`) блок кнопок занимает всю первую flex-линию по высоте, а `<p>` переносится на вторую линию — в column-контейнере новая линия ложится **правее**, а не ниже.

Арифметика на 390 px: контент формы 38,6 … 351,4 px, плюс `column-gap` 24 px → `p.left = 375 px` при ширине экрана 390 px. Совпадает с замером до пикселя.

### Изменение

`src/app/globals.css`, блок `@media (max-width: 768px)`, строки **3539-3547**. Заменить:

```css
  .form-submit {
    align-items: flex-start;
    flex-direction: column;
  }

  .form-submit-actions {
    width: 100%;
  }
```

на:

```css
  /* Grid вместо flex-column: у flex-контейнера с wrap подпись уходила
     на вторую линию, а в column-раскладке линия ложится правее — текст
     оказывался за краем экрана. */
  .form-submit {
    display: grid;
    gap: 1rem;
    align-items: start;
  }

  .form-submit-actions {
    width: 100%;
  }

  .form-submit p {
    max-width: 100%;
  }
```

`flex: 1 1 100%` на `.form-submit-actions` при этом становится неактуальным (у grid-элемента свойство игнорируется) — строку 5126 **не трогать**, она нужна для десктопной раскладки в две кнопки.

Фикс автоматически закрывает и форму в модальном окне: на ≤768 px модалка полноэкранная и использует те же классы.

### Проверка

На 390 px в консоли:
```js
const p = document.querySelector('.form-submit > p').getBoundingClientRect();
// ожидаем: p.left ≈ 38, p.right ≤ 352
```
